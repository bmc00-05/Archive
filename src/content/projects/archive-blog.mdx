<Slide id="problem" title="Problem">
  <Cols n={2}>
    <Stack>
      Jekyll로 운영하던 기존 블로그는 글이 늘어날수록 빌드가 느려졌고, 포트폴리오 사이트와 분리 운영하는 데 따른 비용도 부담이었다.

      - 빌드 30초+ (50개 글)
      - 포트폴리오/블로그 도메인 분리 운영
      - 디자인 일관성 부재
    </Stack>
    <Box>
      > 같은 사람의 두 사이트를 보러 두 URL을 오가야 하는 비효율
    </Box>
  </Cols>
</Slide>

<Slide id="architecture" title="Architecture">
  <Cols n={2}>
    <Stack>
      Astro의 file-based routing 위에 shadcn/ui로 디자인 시스템 구축. MDX Content Collection 두 개(blog/projects)로 콘텐츠 격리.

      - **Framework**: Astro 6 (static + Islands)
      - **Style**: Tailwind v4 + shadcn/ui
      - **Content**: MDX + Content Layer
      - **Deploy**: GitHub Pages + Actions
    </Stack>
    <Box>
      ```text
      src/
      ├── content/
      │   ├── blog/
      │   └── projects/
      ├── pages/
      │   ├── index.astro       (/)
      │   └── portfolio/        (/portfolio)
      ├── layouts/
      └── components/
          ├── ui/   (shadcn)
          ├── mdx/  (Slide, Cols, Stat)
          └── organisms/
      ```
    </Box>
  </Cols>
</Slide>

<Slide id="challenges" title="Technical Challenges">
  <Stack gap="lg">
    <div>
      ### Tailwind v4 마이그레이션
      v3 시절 `@astrojs/tailwind`가 retire되고 `@tailwindcss/vite` + CSS 기반 `@theme inline` 구조로 전환. shadcn CLI(new-york-v4)와 연동.
    </div>
    <div>
      ### Hybrid Doc/Slide Mode
      같은 MDX 콘텐츠를 노션 스타일(세로 스크롤 + TOC)과 파워포인트 스타일(가로 슬라이드 + 키보드 네비) 양쪽으로 렌더. `<Slide>` 래퍼로 명시적 슬라이드 경계 + `scroll-snap-type` 기반 가로 전환.
    </div>
    <div>
      ### Astro 6 Content Layer
      v5 → v6 마이그레이션 중 `defineCollection`에 `loader: glob()` 추가, `entry.render()` → `render(entry)`, `entry.slug` → `entry.id` 일괄 전환.
    </div>
  </Stack>
</Slide>
